# 保存航点状态机飞行

## 1. 保存路线

```bash
cd /home/robot/egohx_ws/26-px4_offboard_control-main
./tools/flight/一键保存航点.sh
```

启动后，在终端按回车执行一次重定位；失败时继续按回车重试，成功前不设次数上限。定位成功后，可在飞行手动控制下，或地面手持设备到目标位置时按回车保存一个点。前四个点兼容命名为
`B1`、`B2`、`C`、`D`，后续点自动命名为 `P005`、`P006`……。四个点完成后，
脚本会把本次采集写入日期目录；完成 B1/B2/C/D 后，当前应用会更新到
`src/race_offboard/config/waypoints/main/`，其中的 `mission.yaml` 包含全部
`route_points`，保存点顺序就是地图规划顺序。旧的当前应用会保留在日期目录。

重复运行保存脚本时，已有同名点默认会被当前位置更新；设置
`FORCE_WAYPOINTS=false` 可改为禁止覆盖。

## 2. 状态机飞行

```bash
./tools/flight/运行航点状态机.sh --manualtakeoff --trosbag --noego
```

参数会传给已有的 `切Offboard后自动起飞0.75米单目标验证.sh`。人工模式下先在
`POSITION/POSCTL` 起飞并悬停，再切到 `OFFBOARD`；状态机检测到 OFFBOARD 后立即
发布第一个保存航点，随后按到达半径依次请求剩余航点。状态机节点只发布
`/goal_pose`，不发布 PX4 setpoint、不解锁、不切换飞行模式。

该入口的自动重定位默认无限重试，直至成功或按 `Ctrl-C` 退出；每次失败会等待新的
同步扫描后继续。设置 `RELOCALIZATION_RETRY_COUNT` 为正整数可恢复有限次数，例如
`RELOCALIZATION_RETRY_COUNT=8 ./tools/flight/运行航点状态机.sh --manualtakeoff --trosbag --noego`。

## 3. 为航点预留行为

行为归档位于 `src/race_offboard/mission/waypoint_behaviors.py`。当前支持五类
可替换命令：

| 行为 | `behavior` | 参数 |
| --- | --- | --- |
| 开启识别程序 | `start_recognition` | 无 |
| 关闭识别程序 | `stop_recognition` | 无 |
| 关闭 EGO，由 A* 接管 | `switch_to_astar` | 无 |
| 同向左转或右转 | `yaw_sweep` | `direction`、`n_deg`、`m_sec`、`cycles` |
| 修改全局速度 | `set_global_speed` | `speed_mps` |

`start_recognition` 会启动 `bs/run_0812.sh`，`stop_recognition` 会停止其整个进程组；
两者仍会发布结构化请求到 `/race/mission/behavior_command` 供记录或其他执行器订阅。
识别程序每个确认结果会打印 UTC 时间戳、类别和置信度。它们不抢占 PX4 setpoint。

可以在 `mission.yaml` 的 `route_points` 条目中增加字段：

```yaml
route_points:
  - name: P005
    x: 1.2
    y: -0.4
    z: 0.75
    state: INSPECT_LEFT
    behavior: yaw_sweep
    behavior_params:
      direction: left
      n_deg: 30
      m_sec: 2
      cycles: 3
    hold_sec: 12.0
```

第四类行为现在是同向累计转动：`direction: left` 时，每次左转 `n_deg`、保持
`m_sec`，重复 `cycles` 次；`direction: right` 时同理向右累计转动。比如左转
45 度、停留 2 秒、重复 2 次，会先到达 `+45` 度并停留，再到达 `+90` 度并停留，
行为结束后保持最终航向，不再发布恢复到到点航向的 `restore` 相位。示例中的
`hold_sec` 应覆盖行为总时长，后续执行节点接入完成确认后可改为确认驱动。

到点判定只检查位置：飞机进入 `arrive_radius`，且高度误差也在该半径内时，状态机立刻
进入该点的停顿状态。每个新生成的航点默认停顿 `0.5s` 后发布下一个航点；状态机不再以
速度或稳定时间阻止切点；飞控侧的高度、失效刹停和遥控接管保护保持不变。需要改动某一
点时，只修改该点的 `hold_sec`：

```yaml
arrive_radius: 0.4
route_points:
- name: B1
  hold_sec: 0.5
```

到达后状态机会发布 `/race/waypoint_fsm/event`、`/race/mission/behavior` 和
JSON 格式的 `/race/mission/behavior_command`。未知行为、非法角度、负时间、非正
速度都会被拒绝，不会被状态机擅自执行。

飞行前必须保持遥控器可接管，确认地图和重定位库与保存航点属于同一坐标系，并
先用低速、短路线验证。离开 OFFBOARD 后状态机会暂停，重新切入不会静默续飞。
