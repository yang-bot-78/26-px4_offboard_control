# 全局路径首次交接修改总结与回退说明

日期：2026 年 8 月 19 日

## 易懂总结

修改前，Super 的同步 A* 算完后会立刻把路径交给 EGO。A* 计算期间 odom 回调被阻塞，因此路径起点可能已经落后于真实飞机位置，EGO 会被旧参考线往回拉。

修改后，A* 结果先进入“等待提交”状态，不会立即发布。Super 必须收到一帧确定发生在 A* 完成之后的新 odom，才会检查飞机到整条待提交路径的距离：

```text
飞机到整条路径的距离 <= 0.15 m，且前向投影合法
    -> 删除已经飞过的路径前缀
    -> 用最新 odom 作为新路径起点
    -> 重新做连续碰撞检查
    -> 第一次提交给 EGO

飞机到整条路径的距离 > 0.15 m，或投影/连接段不安全
    -> 不向 EGO 发布该路径
    -> 用最新 odom 最多重算一次
    -> 第二次仍失败则保持安全等待，直到收到显式目标
```

到旧路径起点的距离 `d_start` 现在只写日志，不参与拒绝判断。因此飞机即使已经沿路线前进了 0.60 m，只要到整条路线的距离仍为 0.03 m，也会正常裁掉旧前缀并提交，不会错误重算。

## 修改范围

### Super 主节点

文件：`src/race_super_planner_ros2/src/super_planner_ros2_node.cpp`

- 增加待提交路径、规划目标编号、odom 代次和源时间戳记录。
- 同步 A* 完成后只保存结果，不再当场发布 global path、local reference 或 local goal。
- 要求至少一帧 A* 完成后的新 odom；定时器先于 odom 到来时保持 `PENDING_FRESH_ODOM`，不误报 `NO_ODOM`，也不重复启动 A*。
- fresh odom 到来后投影到整条 pending 路径，而不是只比较 `path.front()`。
- 提交前裁掉已飞前缀，并用最新 odom 到投影点的短连接段替换旧起点。
- 裁剪后的完整路径复用原有 `validateCompletePath()` 做连续净空和栅格碰撞检查。
- 只允许一次 stale-start 重算；再次拒绝后停止自动重算，避免死回环。重新发送目标（包括相同目标）可以重新解锁规划。
- pending 期间不运行 local-planner watchdog，不清空 EGO 活动轨迹，不重置 Bridge transaction。
- `global_path_id` 只在路径通过首次交接门后递增。

## 与 EGO 实时避障的关系

新 `0.15 m` 门只在一条新 Global path 的首次 `pending -> committed` 交接中存在。提交完成后 pending 状态立即清空，后续 EGO 因实时障碍偏离全局路线 0.30 m 或更大时，不会触发这套新增逻辑。

本次没有修改以下模块：

- EGO 实时点云输入和融合地图；
- 活动轨迹碰撞检查；
- EGO local A*；
- B-spline rebound；
- 执行中实时 replan；
- trajectory bridge 碰撞复检；
- 原有 1.50 m 任务走廊粗安全保护。

本次也没有把 A* 改成异步线程。当前采用的是已审查的最小止血方案：同步规划完成后退出 callback，等待下一帧 fresh odom 再决定是否提交。

## 本次没有修改静态地图

没有改动任何 PCD。当前工作区没有一组可核验的“比赛固定大障碍”坐标、尺寸和高度，不能靠猜测向 `/saved_map` 写障碍。取得实测障碍边界后，应生成新的比赛专用 PCD，并让 Global 和 EGO 同时使用同一份 `/saved_map`，不要直接覆盖原地图。

## 首次验证重点日志

正常流程应依次看到：

```text
[SUPER_PENDING_PATH_READY]
[SUPER_PENDING_PATH_WAIT]          # 可能出现，取决于 callback 调度顺序
[SUPER_PENDING_PATH_COMMIT]
[GLOBAL_PATH]
[SUPER_GLOBAL_PATH_COMPLETE]
```

旧路径偏差过大时应看到：

```text
[SUPER_PENDING_PATH_REJECT] retry=1/1
```

第二次仍失败时应看到：

```text
[SUPER_PENDING_PATH_RETRY_EXHAUSTED]
```

检查 `[SUPER_PENDING_PATH_COMMIT]` 时：

- `d_path` 必须小于等于 0.15 m；
- `d_start_diagnostic` 可以大于 0.15 m，它不再是拒绝条件；
- `committed_points` 必须至少为 2；
- pending 阶段不应提前出现新的 `[GLOBAL_PATH]` 或 local goal 序号递增。
